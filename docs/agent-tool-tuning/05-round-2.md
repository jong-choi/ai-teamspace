# 05. 2차 개선과 측정

[04 문서](04-round-1-scored.md)에서 고른 도구 호출 문제를 고치고 2회 측정했다. 비교 대상은 1차 개선본의 재측정(04 문서, 1회)이다.

| --------------------------------------- | ---------------------------------------------------------------------------------------------- |

## 한계

- 실행 횟수는 2회(52건)다. 비교 대상은 1회(26건)다.
- 04 문서에서 같은 코드의 하네스 통과가 2건 흔들렸다. 그보다 작은 차이는 근거로 쓰지 않는다.
- 이번 회차부터 도구 결과를 60,000자까지 저장했다. 잘린 결과는 0건이다. 비교 대상은 8건이 잘려 있어, 충실도는 온전한 18건의 평균(0.94)과 비교해야 한다.
- 판정 점수 364개가 모두 붙었다.

- 도구 호출 쪽은 나아졌다. 오류는 회당 8회에서 1회로, 필요 없는 호출은 9회에서 1회로, 모델 호출은 케이스당 4.0회에서 2.9회로 줄었다.
- 충실도는 나아지지 않았다. 0.82는 비교 대상의 온전한 18건 평균 0.94보다 낮다. 이번 회차는 충실도를 고치지 않았고, 아래에서 보듯 감점의 절반은 확인하지 않은 알림 전송을 단정한 것이다.
- 지식 그래프 충실도 0.67은 6건 중 4건이 0.5를 받은 값이다. 비교 대상의 1.00은 3건짜리다.
- 내부 ID 노출은 그대로다.

## 도구 오류 메시지

오류는 2회다. 둘 다 스키마 검증 거부이고 메시지는 같다.

```text
인자가 맞지 않아 실행하지 않았습니다.
- mode: 이 도구에 없는 인자입니다.
- limit: 이 도구에 없는 인자입니다.
```

두 번 모두 바로 다음 호출에서 두 인자를 빼고 성공했다. 오류 뒤 같은 도구의 다음 호출 성공은 1.00(2건)이다.

## 도구 결과 충실도

52건 중 1 미만은 17건이다. 모두 원본과 대조했다.

## 시각 정확성

거짓은 52건 중 1건이다.

| 케이스                 | 판정 근거                                  | 원본 대조 |
| ---------------------- | ------------------------------------------ | --------- |
| meeting-create (2회차) | 10월 21일은 수요일인데 금요일이라고 적었다 | 맞는 지적 |

- 1차 개선본에서는 답에 요일을 적은 쓰기 요청 2건이 모두 틀렸다. 이번에는 회의 쓰기 10건 중 요일을 적은 것이 1건뿐이고 그 1건이 틀렸다. 요일 계산이 나아진 것이 아니라 요일을 덜 적은 것이다.
- `meeting-rsvp` 2회차는 UTC 시각과 한국 시각을 나란히 적었다. 틀리지는 않았지만 도구 결과가 UTC뿐이라 생기는 군더더기다.

## 트레이싱

- 52건 모두 채점용 관측(`eval-case`)이 올라갔고 점수 18~19개씩 붙었다.
- 도구 결과가 잘리지 않아 판정 모델이 전체 결과를 봤다. 04 문서에서 잘린 결과 때문에 생긴 잘못된 감점(충실도 4건)은 이번에 없다.
- 판정 모델의 남은 오류는 세 종류다. 거절이 정답인 케이스를 미달성으로 보는 것, 도구 없이 답하는 케이스의 충실도를 0으로 주는 것, 도구 설명에 있는 사실을 근거 없다고 보는 것. 52건 중 5건이다.

## 다음 수정

3차 개선에서 다룬다. 도구 결과 충실도와 응답 품질이 대상이다.

- 쓰기 요청 뒤 확인하지 않은 알림 전송을 단정하는 것.
- 답에 요일을 틀리게 적는 것. 도구 결과에 UTC 시각만 있다.
- 채팅 메시지 결과에 발신자 이름이 없는 것.
- 답에 내부 ID가 나가는 것.
- 기본 파일 도구(`ls`, `grep`)를 부르는 것.
- `wiki_search`에 없는 인자를 넣는 것.

이후 회차로 미룬다.

- 문서에 없는 내용을 채워 넣는 것.
- 그래프에 없는 관계를 관계 표에 섞는 것.
- 승인 전 인자 검증.
