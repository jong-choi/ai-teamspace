# 07. 4차 개선과 측정

[06 문서](06-round-3.md)에서 고른 문제를 고치고 1회 측정했다. 비교 대상은 3차 개선본(06 문서, 2회)이다.

## 고친 것

| 문제 (06 문서)                              | 수정                                                                                                 |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 승인 뒤 쓰기 도구 결과의 시각이 UTC로 나옴  | 시간대를 대화에 남아 있는 맥락 블록에서 읽는다. 승인 뒤 이어 가는 실행에서도 같은 시간대를 쓴다      |
| 쓰기 요청 뒤 알림 전송을 단정               | 회의 생성·취소 도구 설명에서 "참석자에게 알림이 갑니다"를 뺐다. 캘린더에는 알림을 보내는 코드가 없다 |
| 기본 파일 도구(`ls`, `grep`, `glob`)를 부름 | 에이전트 라이브러리가 붙이는 파일 도구 8개를 모델에게 보이지 않게 했다                               |

파일 도구 8개는 `ls`, `read_file`, `write_file`, `edit_file`, `delete`, `glob`, `grep`, `execute`다. 연결된 파일 시스템이 없어 대화마다 비어 있는 가상 폴더만 본다. 시스템 프롬프트는 건드리지 않았다.

같은 회차에 서비스 이름을 AI Teamspace로 바꿨다. 시스템 프롬프트의 제품 이름이 `WorkOS`에서 `AI Teamspace`로 바뀌었다.

## 한계

- 실행 횟수는 1회(26건)다. 비교 대상은 2회(52건)다.
- 같은 코드의 하네스 통과가 2건 흔들린다(04 문서). 1회 측정의 작은 차이는 근거로 쓰지 않는다.
- 판정 점수 182개가 모두 붙었다. 도구 결과가 잘린 건은 없다.
- 이름 변경과 개선이 같은 측정에 들어 있어 둘의 효과를 나눠 볼 수 없다.

## 고친 것의 확인

| 문제                                 | 3차 개선본 (52건)           | 4차 개선본 (26건) |
| ------------------------------------ | --------------------------- | ----------------- |
| UTC로 나온 도구 결과                 | 시각이 든 결과 78개 중 22개 | 35개 중 0개       |
| 회의 쓰기 뒤 알림 전송을 단정        | 회의 쓰기 10건 중 5건       | 5건 중 0건        |
| 파일 도구 호출                       | 5회                         | 0회               |

- 회의 취소의 답은 "취소되었습니다. 취소 사유는 출장이며…"로 끝난다. 3차까지는 두 실행 모두 "참석자에게 알림이 전송되었습니다"가 붙었다.
- 회의 생성의 답은 "2026-10-21(수) 오후 2시 ~ 3시, 온라인 형태로 잡았습니다"다. 요일이 맞고 회의 ID가 없다.
- `wiki-body-edit-unsupported`는 도구를 하나도 부르지 않고 바로 거절했다. 3차까지는 문서를 조회하고 파일 도구로 수정 방법을 찾았다.

## 시각 정확성

거짓 1건은 판정 오류다. `wiki-find-and-read`의 답은 "평일(월~목, 그리고 금요일 오전) 11시부터 오후 4시 사이, 금요일 오후에는 배포가 허용되지 않습니다"이고 위키 내용과 같다. 판정 모델은 금요일도 오후 4시까지 가능하다고 적은 것으로 읽었다.

실제로 틀린 날짜와 시각은 0건이다.

## 도구 호출 정확도

- 도구 호출 43회 중 오류 0회다.
- 판정 모델의 감점 2건 중 `ticket-priority-update`(0.5)는 맞는 지적이다. 티켓을 찾으며 지식 검색을 두 번 더 했다. 결과는 맞다.
- `wiki-body-edit-unsupported`(0)는 판정 오류다. 수정 도구가 없어 거절하는 것이 정답이다.

## 응답 품질

평균 0.96이다. 1 미만은 2건이다.

- `knowledge-incident-response` 0.5: 답에 문서 ID를 적었다.
- `knowledge-relations` 0.5: 관계 표기가 읽기 어렵다.

답에 내부 ID가 나온 것은 `knowledge-incident-response`와 `project-columns-from-screen` 2건이다. 회의·문서·티켓을 만든 뒤 ID를 적던 것은 이번 실행에서 0건이다.

인사에 대한 답에서 에이전트는 자신을 "AI Teamspace 에이전트"라고 소개했다. 3차까지는 "WorkOS 에이전트"였다.

## 트레이싱

- 26건 모두 채점용 관측이 올라갔고 판정 점수가 빠짐없이 붙었다.
- 판정 오류는 26건 중 4건이다(충실도 2건, 도구 선택 1건, 시각 정확성 1건). 종류는 앞 회차와 같고 시각 정확성 1건이 새로 나왔다.

## 남은 문제

- 그래프 관계를 답으로 옮길 때 방향을 흐리거나 없는 관계를 덧붙인다.
- 컬럼 목록이나 문서 안내에 내부 ID를 적는다.
- 결과에 영향이 없는 조회를 끼워 넣는다.
- `wiki_search`에 없는 인자를 넣는다. 이번 실행에서는 0회였다.
- 승인 전 인자 검증이 없다. 에이전트 라이브러리가 승인 단계를 먼저 실행한다.
- 도구 결과가 약 8만 자를 넘으면 라이브러리가 앞부분만 모델에게 준다. 파일 도구를 뺐기 때문에 나머지를 읽을 방법이 없다. 측정에서 가장 큰 결과는 2만 6천 자였다.
