# 화면 로딩 경계

업무 페이지는 Expo Router의 `(workspace)` layout에서 같은 `DashboardShell`을 사용한다. feature 내부의 shell 호출은 공통 shell의 자식 콘텐츠로 처리한다. 페이지 URL은 기존 경로를 유지한다.

조회는 generated Suspense query hook을 사용하고, 실제 데이터를 표시하는 영역에 `DashboardQueryBoundary` 또는 `ChatQueryBoundary`를 둔다. 로딩 fallback은 RNR Skeleton을 사용한다. query 오류는 같은 영역의 ErrorBoundary와 retry 경계에서 처리한다. mutation 오류는 기존 알림 경로를 따른다.

사이드바 멤버 메뉴는 활성 조직을 조회한 뒤 해당 조직의 멤버 관리로 이동한다. 하단 채팅 진입점은 `/chat`으로 연결하며, 미사용 홈·팀·업무 메뉴와 AI 엔진 상태 카드는 표시하지 않는다.

## 화면별 경계

| 화면                         | 조회 및 표시 경계                                          | 유지하는 영역                                      |
| ---------------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| 홈                           | 업무 데이터 조회 없음                                      | 공통 shell 및 홈 콘텐츠                            |
| 프로젝트 전체                | 프로젝트 카드 목록, 보기 선택 정보, 생성 폼의 멤버 조회    | `프로젝트 / 전체 프로젝트`, 새 프로젝트 버튼       |
| 프로젝트 보드·목록           | 프로젝트 이름, 필터 자료, 티켓 본문, 열린 생성·상세 화면   | 보기 전환, 생성 버튼, 필터 상태 및 검색어          |
| 회의일정 월간·주간·일간·목록 | 회의 이벤트·목록, 보조 일정, 회의실 필터·현황, 열린 dialog | 헤더, 기간 이동, 검색·필터, 날짜 선택 UI           |
| 회의 상세·예약·일정 변경     | 열린 dialog의 자료 및 내부 조회 경계                       | 뒤의 업무 화면, dialog의 닫기 동작                 |
| 위키                         | 초기 tree 조회, 선택 문서의 본문, history·관리 dialog      | 문서 조회 중 breadcrumb·탐색 tree 및 본문 로딩 틀  |
| 채팅                         | 채널 목록, 대화 정보, 메시지 feed의 독립 경계              | sidebar 검색·생성·닫기, 메시지 작성 영역           |
| 메시지 상세·수정             | 선택 메시지·작성자 자료                                    | 메시지 상세·수정 헤더 및 뒤로가기                  |
| 조직 멤버                    | 초기 접근 정보, 통계, 멤버·초대 목록의 독립 경계           | 접근 확인 후 제목, 목록 검색·역할·페이지 상태      |
| 조직 초대 상세               | 수신자와 초대 상태를 확인하는 상세 카드 경계               | 공통 shell                                         |
| MCP 권한 설정                | 요약·개인 권한·조직 정책별 경계                            | 설정 제목과 설명                                   |
| AI 대화                      | 대화 목록과 선택 대화의 독립 경계                          | 다른 쪽 대화 영역, 공통 shell                      |
| Agent 외부 연결              | 연결 목록, 펼친 연결의 도구 catalog                        | 외부 연결 제목·작성 폼 및 입력 상태                |
| 로그인·가입                  | Suspense 업무 조회 없음                                    | 인증 폼과 입력 상태                                |
| 온보딩                       | 로그인·활성 조직 확인에 필요한 초기 접근 경계              | 조직 생성 폼 표시 이후에는 추가 Suspense 조회 없음 |
| OAuth 복귀                   | 업무 데이터 query 없음                                     | 인증 callback 제어 흐름                            |

로그인·활성 조직·접근 정보는 초기 접근을 결정하는 조회다. 해당 정보가 없는 동안 보호된 업무 데이터를 표시하지 않는다. 데이터가 확인된 뒤의 목록·필터·문서 전환은 각 데이터 영역에서 처리한다.

## 캘린더 날짜 선택

`CalendarWorkspace`는 날짜·보기·검색·필터와 dialog 상태를 소유한다. 회의 query는 `CalendarMeetingContent`가, 보조 일정 query는 `CalendarMiniPanelContent`가 소비한다. 회의실 선택·현황은 각각 별도 조회 경계를 사용한다.

회의 로딩 fallback도 실제 월간 날짜 격자 또는 주간·일간 시간 축을 표시한다. RNR Skeleton은 회의 카드·일정 표시 영역에만 나타난다. 보조 달력의 날짜 및 월 이동 버튼은 회의 데이터 로딩 중에도 사용할 수 있다. 목록 보기에서는 목록 데이터 영역만 Skeleton으로 표시한다.

회의실 타임라인 query는 `CalendarRoomsContent`를 열린 dialog 내부에 mount한 경우에만 실행한다. 닫힌 창의 일간 query 때문에 날짜 선택이나 월간 화면을 로딩 상태로 바꾸지 않는다.

## 참석자와 주최자

회의 주최자는 관리 권한을 위한 정보이며 참석자 목록과 구분한다. 실제 참석자는 `meeting_attendee`에 저장된 명시적 목록이다. 생성 폼은 로그인 사용자를 기본 선택하지만 사용자가 삭제할 수 있고, 본인도 조직 멤버 검색에서 다시 추가할 수 있다.

인원·RSVP·참석자 검색·ICS 참석자·일정 충돌은 명시한 참석자 목록을 기준으로 한다. 주최자라는 이유로 자동 포함하거나 저장 후 복원하지 않는다. 이전 회의에도 참석자 row가 없는 주최자를 임의로 참석자에 추가하지 않는다.

## 검증

- 계정 표시와 본인 참석자 제거·재추가는 component test로 확인한다.
- 본인의 저장·제거·재조회와 비참석 주최자의 충돌 제외는 실제 DB integration test로 확인한다.
- 실제 browser에서 빈 cache·지연 응답·연속 날짜 선택을 적용하여 헤더·검색·날짜 선택을 유지하는지 확인한다.
- 공통 shell, 헤더·입력 상태 보존과 부분 Skeleton 표시를 확인하고, root format·lint·typecheck 및 generated contract 검사를 수행한다.
