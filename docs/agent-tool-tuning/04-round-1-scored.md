# 04. 1차 개선본을 다시 측정하고 Langfuse 점수로 채점

[02 문서](02-round-1.md)와 같은 코드(1차 개선본)를 한 번 더 돌리고 Langfuse 점수로 채점했다. 비교 대상은 같은 방식으로 채점한 [고치기 전 상태](03-baseline-scored.md)다.

코드는 02 문서 때와 같다. 달라진 것은 채점 방식뿐이다.

## 한계

- 도구 결과를 6,000자까지만 저장한 실행 기록이다. 결과가 그보다 긴 8건은 판정 모델이 잘린 결과를 보고 채점했다. 전체 평균과 함께 온전한 18건의 평균을 적는다. 다음 회차부터는 60,000자까지 저장한다.
- 판정 점수 182개가 모두 붙었다.
- 실행 횟수는 1회다.

## 도구 호출 정확도

남은 문제를 실행 기록에서 확인했다. 판정 모델의 근거와 일치한다.

| 문제                                  | 케이스                                                                      | 근거                                                                  |
| ------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 값 없는 선택 인자를 빈 값으로 채움    | members-admins, chat-messages-read, meeting-reschedule, knowledge-relations | 오류 8건 중 5건. 한 번씩 거부된 뒤 바로 고침                          |
| 없는 회의 분류 값을 보냄              | meeting-create, meeting-create-in-room                                      | `meeting`을 보내 거부됨. 승인이 한 번 더 필요했음                     |
| 온라인 회의를 기타 장소로 만듦        | meeting-create                                                              | 장소 유형을 `online`이 아니라 `other`로 보냄                          |
| 회의실을 지정하지 못함                | meeting-create-in-room                                                      | 회의실 ID를 얻을 도구가 없어 검색 6번 뒤 장소를 글자로 적음. 승인 3번 |
| 참석자 필터에 본인 ID를 넣음          | meeting-reschedule                                                          | 주최한 회의가 빠져 빈 결과가 나오고, 필터를 빼고 다시 조회함          |

| 안 바꾸는 필드까지 다시 보냄          | ticket-priority-update, wiki-rename                                         | 결과는 맞음                                                           |

요청한 일을 못 한 것은 `meeting-create-in-room` 한 건이다. 회의는 만들었지만 회의실이 예약되지 않았다. 판정 모델은 이 건의 요청 달성을 참으로 매겼다. 회의가 만들어졌다는 것만 보고 회의실이 빠진 것은 놓쳤다.

## 도구 오류 메시지

오류 8건은 모두 스키마 검증 거부다. 오류 뒤 같은 도구의 다음 호출이 성공한 비율은 0.72다.

- 오류가 난 6건 중 4건은 같은 도구의 바로 다음 호출에서 고쳤다.
- `meeting-create-in-room`은 회의 생성에서 인자 두 개가 틀렸는데 하나만 고쳐 다시 보내 한 번 더 거부됐다. `wiki_search`에 없는 인자를 넣어 거부된 뒤에는 그 도구를 다시 부르지 않았다.
- `knowledge-relations`는 거부된 회의 목록 조회를 다시 부르지 않고 답을 냈다. 필요 없는 호출이었다.

## 도구 결과 충실도

전체 0.85, 도구 결과가 온전한 18건은 0.94다.

판정 모델이 0.5를 준 9건을 원본과 대조했다.

| 케이스                      | 판정 근거                                       | 원본 대조                                        |
| --------------------------- | ----------------------------------------------- | ------------------------------------------------ |
| meetings-list-week          | 14~16일 회의가 도구 결과에 없다                 | 잘린 결과 탓. 실제로는 결과에 있다               |
| chat-conversations-list     | 도구 결과에 없는 채팅방을 적었다                | 잘린 결과 탓                                     |
| chat-messages-read          | 발신자 이름이 도구 결과에 없다                  | 잘린 결과 탓. 이름은 대화 목록 결과에 있다       |

- 9건 중 4건은 잘린 결과 때문에 생긴 잘못된 감점이다.
- 실제 충실도 문제는 3건이다. 문서에 없는 내용을 채워 넣는 것(2건)과 확인하지 않은 알림 전송을 단정하는 것(1건)이다.
- 지식 그래프 충실도는 3건 모두 1.0이다. 이번 실행에서는 그래프에 없는 관계를 그래프 관계처럼 적지 않았다. 02 문서의 측정에서는 같은 코드로 6개를 지어냈다. 한 번의 실행으로는 나아졌다고 말할 수 없다.

## 시각 정확성

거짓 3건이다.

| 케이스             | 판정 근거                                  | 원본 대조                           |
| ------------------ | ------------------------------------------ | ----------------------------------- |
| meeting-create     | 10월 21일은 수요일인데 금요일이라고 적었다 | 맞는 지적                           |
| meeting-reschedule | 10월 16일은 금요일인데 월요일이라고 적었다 | 맞는 지적                           |
| meetings-list-week | 14~16일 회의가 데이터에 없다               | 잘린 결과 탓. 답의 요일은 모두 맞다 |

답에 요일을 적은 쓰기 요청 2건이 모두 요일을 틀렸다. 02 문서의 측정에서도 같은 2건이 틀렸다. 도구 결과에는 UTC 시각만 있고 요일은 없어서 모델이 직접 계산한다.

## 응답 품질

전체 0.93이다. 1 미만은 5건이다.

- `project-columns-from-screen` 0.5: 묻지 않은 컬럼 ID를 표에 넣었다.
- `chat-messages-read` 0.3: 잘린 결과 탓에 이름을 지어냈다고 본 잘못된 감점이다.
- `chat-conversations-list` 0.8, `knowledge-refund-settlement` 0.8: 필요 이상의 설명과 내부 ID.
- `project-progress` 0.9: 프로젝트 키와 후속 제안을 덧붙였다.

판정 모델은 내부 ID 노출에 관대하다. 기계 점수로는 26건 중 8건(0.31)의 답에 ID가 있는데 품질 점수에서 감점된 것은 2건이다. ID 노출은 기계 점수로 본다.

## 트레이싱

- 실행 트레이스와 별도로, 케이스마다 채점용 관측(`eval-case`) 하나가 Langfuse에 올라간다. 요청, 도구 호출과 결과, 최종 답이 한 관측에 들어 있고 점수 18개가 여기에 붙는다.
- 판정 모델의 실행도 각각 트레이스로 남아 프롬프트와 출력을 볼 수 있다.
- 회차 이름으로 걸러 두 회차의 점수 평균을 Langfuse 화면에서 비교할 수 있다.

## 다음 수정

2차 개선에서 다룬다:

- 값 없는 선택 인자를 빈 값으로 채우는 것. 설명으로는 안 고쳐지므로 모델 응답 단계에서 그런 인자를 뺀다.
- 회의실 목록 도구 추가.
- 참석자 필터가 주최한 회의도 포함하게 한다.
- 회의 분류, 장소 유형, 참석 응답 값, 우선순위 값의 설명 보강.

이후 회차로 미룬다:

- 답에 요일을 틀리게 적는 것.
- 문서에 없는 내용을 채워 넣는 것, 확인하지 않은 알림 전송을 단정하는 것.
- 답에 내부 ID가 나가는 것.
- 승인 전 인자 검증. 에이전트 라이브러리가 승인 단계를 먼저 실행하도록 고정돼 있어, 넣으려면 승인 기능 자체를 바꿔야 한다.
