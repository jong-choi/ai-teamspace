# 03. 고치기 전 상태를 Langfuse 점수로 다시 채점

[측정 1](01-baseline.md)의 실행을 다시 돌리지 않고, 그때 저장된 실행 기록 26건을 Langfuse에 올려 점수를 매겼다. 01 문서의 O/△/X 판정은 사람이 읽고 내린 것이고, 이 문서의 점수는 Langfuse 평가기가 매긴 것이다. 이후 회차는 모두 이 방식으로 채점한다.

채점 방법은 [README](README.md#점수)에 있다.

## 한계

- 이 회차의 실행 기록은 도구 결과를 6,000자까지만 저장했다. 결과가 그보다 긴 9건은 판정 모델이 잘린 결과를 보고 채점했다. 채팅방 목록처럼 결과가 긴 케이스에서 "도구 결과에 없는 내용을 지어냈다"고 잘못 판정한 것이 원본 대조로 확인된다. 그래서 전체 평균과 함께, 도구 결과가 온전히 저장된 17건만의 평균을 같이 적는다.
- 판정 점수 182개 중 1개가 붙지 않았다. 판정 모델의 출력이 형식을 벗어난 경우다.
- 실행 횟수는 1회다.

## 판정 모델이 짚은 것

판정 근거는 Langfuse의 각 점수에 코멘트로 저장돼 있다. 낮은 점수의 근거를 유형별로 묶었다.

**답이 없거나 내부 글자가 나감 (7건).** `project-progress`, `ticket-create-with-due`, `wiki-body-edit-unsupported`, `meeting-create`, `meeting-create-in-room`, `meeting-reschedule`, `meeting-rsvp`. 충실도, 품질, 달성이 모두 0이다. 01 문서의 판정과 같다.

**도구 호출이 헛돎.** 도구 선택 0.5의 근거는 대부분 "결국 맞는 도구를 썼지만 스키마 오류로 같은 도구를 여러 번 다시 불렀다"이다. `members-admins`(오류 10회), `meetings-list-week`, `chat-messages-read`가 그렇다.

**문서에 없는 내용을 덧붙임.**

- `wiki-find-and-read`: 금요일 배포 시간을 11시~12시로 구체화한 것은 문서에 없는 추론이라고 짚었다. 시각 정확성도 거짓으로 매겼다.
- `knowledge-incident-response`: 채널 이름 예시가 문서에 없다고 짚었다.
- `ticket-priority-update`: "높은 우선순위로 처리될 수 있습니다"가 도구 결과에 없다고 짚었다.

**지식 그래프에 없는 관계를 적음.**

- `knowledge-refund-settlement` 0.4: 환불과 정산, 정산서의 관계는 그래프와 일치하지만 정산 차감, 정산서 표시, 티켓·프로젝트 관계는 그래프에 없다.
- `knowledge-relations` 0.5: 관계 2개는 그래프에 있지만 운영 배포와 DB를 Go/No-Go 회의와 연결한 것은 그래프에 없다.

**언어.** `ticket-move-to-review`는 한국어 요청에 영어로 답했다.

## 판정 모델과 사람 판정이 다른 곳

01 문서의 판정과 대조했다.

| 케이스                  | 판정 모델                          | 사람 판정 (01 문서)                 | 어느 쪽이 맞나                                        |
| ----------------------- | ---------------------------------- | ----------------------------------- | ----------------------------------------------------- |
| chat-conversations-list | 충실도 0, 달성 거짓                | 충실도 O                            | 사람. 판정 모델은 잘린 도구 결과를 봤다               |
| chat-messages-read      | 충실도 0.5 (발신자 이름 근거 없음) | 충실도 △ (다른 이유)                | 사람. 이름은 잘린 대화 목록 결과에 있다               |
| members-admins          | 충실도 1                           | 충실도 X (12명 중 10명만 보고 단정) | 사람. 판정 모델은 조회되지 않은 멤버를 알 수 없다     |
| meetings-list-week      | 충실도 1, 달성 참                  | 충실도 △ (11건 중 5건만 답함)       | 사람. 같은 이유다                                     |
| knowledge-relations     | 충실도 0.5 (방향을 틀리게 적었다)  | 방향까지 맞게 옮김                  | 사람. 답은 방향을 맞게 적었고 판정 모델이 잘못 읽었다 |

판정 모델은 실행 기록 안에서 답과 도구 결과가 어긋나는 것은 잘 잡는다. 도구가 일부만 돌려준 것을 전체로 착각한 답은 잡지 못한다. 실행 기록 밖의 사실이 필요하기 때문이다.

## 01 문서와 같은 결론

- 쓰기 요청 12건 중 요청 달성이 참인 것은 5건이다.
- 오류가 난 뒤 같은 도구의 다음 호출이 성공한 비율이 0.24다. 오류 문구가 원인을 알려 주지 않아 고치지 못한다는 01 문서의 관찰과 맞는다.
- 필요 없는 호출 48회의 대부분은 오류 뒤에 부른 `grep`이다.
