# 02. 1차 개선과 측정 2

[측정 1](01-baseline.md)에서 가장 큰 원인으로 확인된 것부터 고치고 다시 쟀다. 실행 횟수는 1회다.

## 무엇을 고쳤나

### 인자 오류 문구

모델이 보낸 인자가 스키마와 안 맞으면 어느 인자가 왜 틀렸는지를 알려 준다.

고치기 전에 모델이 받던 문구는 원인이 없는 한 줄과 수십 줄짜리 서버 호출 스택이었다. 지금은 이렇게 나간다.

```text
인자가 맞지 않아 실행하지 않았습니다.
- category: 허용 값은 team, sprint, 1on1, allhands, client 중 하나입니다.
- recurrence: 값이 없으면 인자를 생략합니다.
```

- 틀린 인자를 한 번에 모두 알려 준다.
- 허용 값 목록, 숫자 범위, 시각 형식 예시를 함께 적는다.
- 빈 문자열이나 `null`로 채운 선택 인자는 생략하라고 알려 준다.
- 도구에 없는 인자도 거부한다. 전에는 조용히 버려졌다.
- 구현은 [tool-input-feedback.middleware.ts](../../server/src/agent/infrastructure/deep-agent/tool-input-feedback.middleware.ts)에 있다. MCP 도구 전체에 적용된다.

### 도구 설명

26개 중 24개를 고쳤다. 글자 수는 3,045자에서 1,635자가 됐다.

- 권한 검증과 내부 구현을 설명하는 문장을 뺐다. 모델이 도구를 고르는 데 쓰이지 않는 내용이다.
- 무엇을 돌려주는지, 필요한 ID를 어디서 얻는지를 적었다.

| 도구                          | 전                                                                                                                                             | 후                                                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `projects_list`               | 명시한 조직의 프로젝트 목록을 조회합니다. projects:read scope와 현재 조직 멤버십을 모두 검증합니다.                                            | 조직의 프로젝트 목록을 조회합니다. 프로젝트마다 진행 중 티켓 수(activeTicketCount)와 완료 티켓 수(doneTicketCount)가 들어 있습니다.          |
| `wiki_document_update`        | 명시한 조직의 위키 문서 metadata를 수정합니다. 기존 revision/concurrency 및 hierarchy 규칙을 우회하지 않으며 현재 조직 접근 권한이 필요합니다. | 위키 문서의 제목이나 위치를 바꿉니다. 본문은 수정할 수 없습니다. 바꿀 인자만 넣습니다.                                                       |
| `calendar_meeting_reschedule` | 기존 회의 또는 recurrence 범위의 일정을 변경합니다. 현재 수정 권한, 시간/장소 규칙, 충돌 검증을 적용하고 참석자 일정에 영향을 줄 수 있습니다.  | 회의의 시간과 장소를 바꿉니다. 장소를 그대로 두려면 calendar_meeting_get 결과의 locationType, meetingRoomId, locationText를 그대로 넣습니다. |

인자 설명이 0개에서 23개(792자)가 됐다. 측정 1에서 모델이 실제로 잘못 쓴 인자에만 붙였다.

나머지는 [도구 정의 파일](../../server/src/mcp/tools)에 있다.

### 입력 스키마

티켓 마감 시각(`dueAt`)이 `+09:00` 같은 오프셋 형식을 받는다. 전에는 `Z`로 끝나는 형식만 받았다. 캘린더 도구, 시스템 컨텍스트와 형식이 같아졌다. REST 계약도 같이 바뀌어 클라이언트 생성물 2개가 갱신됐다.

입력 스키마 글자 수는 인자 설명이 늘어서 19,255자에서 20,552자가 됐다.

| -------------------------- | --------------------------- | ------ | ------------------------------- |
| 선택 인자를 빈 값으로 채움 | 캘린더 케이스 전부에서 반복 | 5건    | 5건 모두 고침                   |
| 없는 값을 지어냄           | 같은 값을 여러 번 다시 보냄 | 3건    | 3건 모두 고침                   |

- 모델은 여전히 첫 호출에서 선택 인자를 빈 값으로 채우고 없는 분류 값을 지어낸다. 인자 설명과 도구 설명으로는 이 습관이 없어지지 않았다.
- 달라진 것은 오류를 받은 다음이다. 틀린 인자와 허용 값을 받으면 한 번에 고친다.
- `grep`이 36회에서 6회로 줄었다. 오류 뒤에 도구 설명을 찾아 헤매는 일이 거의 없어졌다. 남은 6회 중 5회는 `meeting-rsvp` 한 건에서 나왔다.

### 설명을 고친 효과

- `project-progress`: 프로젝트 목록에 티켓 수가 있다는 설명을 보고 한 번에 답했다.
- `members-admins`: 역할 필터 설명을 보고 관리자만 조회했다.
- `wiki-body-edit-unsupported`: 본문은 수정할 수 없다는 설명을 보고 수정 도구를 부르지 않았다.
- `ticket-create-with-due`: 마감 시각이 오프셋 형식을 받게 되어 첫 호출이 그대로 통과했다.

### 설명으로 안 고쳐진 것

- 참석자 필터: 설명을 붙였지만 `meeting-reschedule`, `meeting-cancel`에서 여전히 본인 ID를 넣었다. 첫 조회가 비어서 다른 방법으로 돌아갔다. 주최한 회의를 빼는 필터 동작 자체가 모델의 예상과 다르다.
- 장소 유형: `meeting-create`에서 온라인 회의를 `other`로 보냈다. 붙인 설명이 `meeting_room`과 `other`만 다루고 `online`을 말하지 않는다.
- 바꿀 인자만 넣기: `ticket-priority-update`, `wiki-rename`에서 안 바꾸는 필드까지 다시 보냈다.

### 새로 보인 문제

- `ticket-priority-update`가 실패로 바뀌었다. "긴급"을 `high`로 옮겼다. 이번 변경과 직접 이어지는 원인은 찾지 못했다. 우선순위 인자에는 설명이 없고, 측정 1에서는 맞게 보냈다. 1회 측정이라 우연인지는 다음 측정에서 본다.
- `meeting-create-in-room`은 오류가 줄었지만 결과는 여전히 틀렸다. 회의실 ID를 얻을 도구가 없어서 장소를 글자로 적는 쪽으로 빠졌다.

### 남은 실패 3건의 원인

| 케이스                 | 원인                                           |
| ---------------------- | ---------------------------------------------- |
| ticket-priority-update | "긴급"을 `high`로 옮김                         |
| meeting-create         | 온라인 회의의 장소 유형을 `other`로 보냄       |
| meeting-create-in-room | 회의실 목록 도구가 없어 회의실을 지정하지 못함 |

## 도구 오류 메시지

자연스럽게 난 오류 10건이다.

| 종류             | 건수 | 모델이 받은 문구            | 다음 호출에서 고쳤는가 |
| ---------------- | ---- | --------------------------- | ---------------------- |
| 스키마 검증 거부 | 8    | 틀린 인자별 한 줄과 허용 값 | 8건 모두 고침          |
| 티켓 없음        | 2    | `티켓을 찾을 수 없습니다.`  | 원래 티켓으로 돌아감   |

- 새 문구는 의도대로 동작했다. 한 문구에 틀린 인자가 5개까지 나왔고 모델은 5개를 한 번에 고쳤다.
- 쓰기 도구의 인자 오류는 여전히 승인 뒤에 드러난다. 승인 요청 14회 중 3회는 거부될 호출에 대한 것이었다.

## 도구 결과 충실도

O 15건, △ 4건, X 7건이다. 측정 1은 O 11건, △ 6건, X 2건, 답 없음 7건이었다.

도구 결과와 다른 답 7건:

| 케이스                      | 틀린 내용                              | 측정 1에서는            |
| --------------------------- | -------------------------------------- | ----------------------- |
| wiki-find-and-read          | 문서에 없는 금요일 오전 배포 시간      | 같은 내용을 지어냄      |
| meetings-list-week          | 요일 전부, 회의 범위                   | 요일을 적지 않았음      |
| knowledge-relations         | 그래프에 없는 관계 6개                 | 지어낸 관계 2개         |
| knowledge-incident-response | 문서에 없는 절차 여러 개               | 예시 하나를 덧붙인 정도 |
| ticket-priority-update      | `high`로 바꾸고 긴급으로 바꿨다고 답함 | 맞게 답함               |
| meeting-create              | 요일, 자동 생성 링크                   | 답 없음                 |
| meeting-reschedule          | 옮기기 전 시각, 요일                   | 답 없음                 |

반복되는 유형 세 가지:

- **요일과 시각 계산이 틀린다.** 요일을 적은 3건이 모두 틀렸다. 시스템 컨텍스트는 오늘 날짜와 요일을 주는데, 모델은 다른 날짜의 요일을 거기서 계산하다 틀린다. UTC 시각을 KST로 바꾸다 틀리거나 바꾸지 않고 적는 경우도 2건 있다.
- **지식 그래프에 없는 관계를 그래프 관계처럼 적는다.** 그래프가 돌려준 관계는 두 회차 모두 정확히 옮겼다. 문제는 다른 도구에서 읽은 값이나 추측을 같은 표에 관계 이름을 붙여 넣는 것이다.
- **문서 내용을 늘려 쓴다.** 문서가 4줄로 적은 절차를 7단계로 풀면서 문서에 없는 세부를 채운다.

지식 그래프 호출 자체는 나아졌다. 없는 검색 방식 값을 보내는 일이 없어졌고(측정 1에서 7회), 관계를 물은 케이스에서 검색, 맥락 조회 순서로 불렀다.

이 결과만으로 1차 개선이 충실도를 떨어뜨렸다고 말할 수는 없다. 틀린 7건 중 2건은 측정 1에서 답이 없던 케이스고, 1건은 측정 1과 똑같이 틀렸다. 나머지 4건은 같은 도구 결과를 받고 답만 달라졌다. 다만 충실도가 지금 가장 약한 축이라는 점은 분명하다.

## 트레이싱

- 26개 케이스의 실행 40개가 모두 Langfuse 트레이스와 연결됐다.
- 실행당 모델 호출과 토큰이 줄어든 것이 트레이스에서도 보인다.
- 인자 오류로 거부된 호출은 이번에도 도구 관측으로 남지 않는다. 새 오류 문구는 도구 실행 전에 돌려주기 때문이다. 거부 문구에서 서버 파일 경로와 조직 ID는 없어졌다.
- 충실도와 응답 품질 판정은 Langfuse 점수로 올리지 않았다.

## 사용량

## 다음 수정

2차 개선 후보를 원인이 확인된 순서로 적는다.

도구 호출:

- 쓰기 도구의 인자를 승인 전에 검증한다. 거부될 호출을 사용자가 승인하는 일을 없앤다.
- 회의 목록의 참석자 필터가 주최한 회의도 포함하게 하거나, 모델이 본인 ID를 넣지 않게 한다.
- 회의실 목록 도구를 추가한다.
- 장소 유형 설명에 `online`을 넣는다. 우선순위 값의 순서를 설명에 적는다.

충실도:

- 답에 요일을 틀리게 적는 것을 줄일 방법을 찾는다. 오늘 요일은 이미 시스템 컨텍스트에 있다.
- 도구 결과의 시각이 UTC로만 나가는 것을 검토한다.
- 지식 그래프 결과와 다른 도구 결과가 답에서 섞이는 것을 줄일 방법을 찾는다.

응답 품질:

- 쓰기 도구 결과에 들어 있는 내부 영수증과 ID가 답으로 새는 것을 줄인다.
