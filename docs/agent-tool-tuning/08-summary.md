# 08. 전체 결과

데모 시드 환경에서 케이스 26개로 에이전트의 도구 호출을 재고, 네 번 고치며 다시 쟀다. 회차별 근거는 각 문서에 있다.

| 회차       | 문서                        | 실행 횟수 | 건수 |
| ---------- | --------------------------- | --------- | ---- |
| 고치기 전  | [03](03-baseline-scored.md) | 1회       | 26   |
| 1차 개선본 | [04](04-round-1-scored.md)  | 1회       | 26   |

- 1차 개선본은 한 번 더 돌렸다([02](02-round-1.md)). 같은 코드로 하네스 통과가 22건과 24건으로 갈렸다. 1회 측정에서 2건 이하의 차이는 근거가 되지 못한다.
- 고치기 전과 1차 개선본은 도구 결과를 6,000자까지만 저장했다. 판정 모델이 잘린 결과를 본 건이 각각 9건, 8건 있다. 2차부터는 잘린 건이 없다.
- 판정 모델은 에이전트와 같은 `gpt-oss:120b`다.

## 판정 모델의 한계

원본과 대조해 판정이 틀린 것으로 본 건수다.

| 회차 | 건수        | 종류                                                                            |
| ---- | ----------- | ------------------------------------------------------------------------------- |
| 2차  | 52건 중 5건 | 거절이 정답인 케이스를 미달성으로 봄, 도구 없이 답하는 인사의 충실도를 0으로 줌 |
| 3차  | 52건 중 4건 | 위와 같음                                                                       |
| 4차  | 26건 중 4건 | 위와 같음. 맞게 적은 시간대를 틀렸다고 본 1건 추가                              |

- `wiki-body-edit-unsupported`와 `smalltalk-no-tool` 두 케이스는 매 회차 잘못 감점된다. 평균 점수는 그만큼 낮게 나온다.
- 판정 모델은 도구 결과만 보고 도구 설명은 보지 않는다. 도구 설명에 있는 사실을 근거 없다고 본다.
- 평균의 작은 차이보다 원본과 대조한 건수를 근거로 삼았다.

## 남은 문제

- 지식 그래프 관계를 답으로 옮길 때 방향을 흐리거나 없는 관계를 덧붙인다. 네 회차 동안 그대로다.
- 컬럼 목록이나 문서 안내에 내부 ID를 적는다(4차 26건 중 2건).
- 결과에 영향이 없는 조회를 끼워 넣는다.
- `wiki_search`에 `knowledge_search`의 인자를 섞어 넣는다(2차 2회, 3차 1회, 4차 0회).
- 승인 전 인자 검증이 없다. 에이전트 라이브러리가 승인 단계를 먼저 실행해, 틀린 인자도 승인 요청까지 간다.
- 도구 결과가 약 8만 자를 넘으면 모델은 앞부분만 받는다. 측정에서 가장 큰 결과는 2만 6천 자였다.
- 4차는 1회 측정이다. 오류 0회와 헛호출 0회가 유지되는지는 더 돌려 봐야 안다.
- 티켓 목록 도구가 없어 티켓을 제목으로 찾을 때 지식 검색을 거친다.
