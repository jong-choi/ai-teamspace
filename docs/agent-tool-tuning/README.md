# 에이전트 도구 호출 튜닝 기록

AI Teamspace 에이전트의 시스템 프롬프트, MCP 도구 설명, 인자 설명, 입력 스키마, 도구 오류 메시지를 고치면서 잰 결과를 회차별로 남긴다. 문구는 필요한 내용만 간결하게 쓴다. 분량을 줄이는 것이 목표는 아니다.

## 측정 방법

- 대상은 데모 시드(한라봉 스튜디오)가 들어간 평가 전용 환경이고, 데모 계정 `doyun.kim`으로 실행한다.
- 케이스는 [tool-calling 데이터셋](../../evals/agent/datasets/tool-calling/tool-calling.json) 26개다. 읽기 11, 지식 그래프 3, 쓰기 12.
- 한 번의 측정은 세 가지를 함께 한다.
  - 벤치마킹: 하네스가 도구 선택, 인자, 승인 흐름, 최종 상태를 기계적으로 채점한다.
  - 트레이싱: 같은 실행을 로컬 Langfuse에 남긴다.
  - 판정: 대화 원본을 직접 읽고 실패 원인, 도구 결과를 답에 충실히 반영했는지, 응답 품질을 평가한다.
- 평가 우선순위는 도구 호출 정확도, 지식 그래프를 포함한 도구 결과 충실도, 응답 품질 순이다.
- 실행 방법은 [evals/agent README](../../evals/agent/README.md)의 Seeded workspace runs를 따른다.
- 대화 원본과 트레이스는 저장소에 넣지 않는다.

## 점수

03 문서부터는 Langfuse 점수로 채점한다. 케이스 하나의 실행 기록(요청, 도구 호출과 결과, 최종 답)을 Langfuse 관측 하나로 올리고, 거기에 점수를 붙인다.

판정 모델이 매기는 점수 7개. Langfuse의 LLM 평가기가 에이전트와 같은 모델(`gpt-oss:120b`)로 채점하고 근거를 코멘트로 남긴다.

| 점수                           | 형식   | 무엇을 보나                               |
| ------------------------------ | ------ | ----------------------------------------- |
| `tool_selection`               | 0~1    | 요청에 맞는 도구를 필요한 만큼만 불렀는가 |
| `faithfulness`                 | 0~1    | 답의 사실이 도구 결과에 있는가            |
| `knowledge_graph_faithfulness` | 0~1    | 그래프가 준 관계만 관계로 적었는가        |
| `answer_quality`               | 0~1    | 요청에 바로 답했는가, 군더더기가 없는가   |
| `task_completed`               | 참거짓 | 시킨 일을 끝냈는가                        |
| `language_match`               | 참거짓 | 요청과 같은 언어로 답했는가               |
| `datetime_accuracy`            | 참거짓 | 답에 적은 날짜·요일·시각이 맞는가         |

기계적으로 세는 점수 12개. 하네스 결과와 실행 기록에서 계산해 Langfuse에 올린다.

| 점수                                                       | 무엇을 세나                                        |
| ---------------------------------------------------------- | -------------------------------------------------- |
| `harness_pass`                                             | 하네스 통과 여부                                   |
| `first_call_ok`                                            | 첫 도구 호출이 오류 없이 성공했는가                |
| `error_recovery`                                           | 오류가 난 뒤 같은 도구의 다음 호출이 성공한 비율   |
| `tool_errors`                                              | 오류로 끝난 도구 호출 수                           |
| `unneeded_calls`                                           | 파일 도구 호출, 없는 도구 호출, 똑같은 호출의 반복 |
| `extra_approvals`                                          | 기대보다 더 요청한 승인 수                         |
| `internal_id_leak`                                         | 답에 UUID나 내부 ID가 있는가                       |
| `answer_chars`                                             | 답의 글자 수                                       |
| `model_calls`, `input_tokens`, `output_tokens`, `cost_usd` | 케이스당 비용                                      |

- 채점 방법과 실행 명령은 [langfuse-setup.md](langfuse-setup.md)에 있다.
- 판정 모델의 점수는 원본과 대조해 틀린 판정을 리포트에 적는다.
- 01, 02 문서는 사람이 원본을 읽고 O, △, X로 매긴 판정이다. 기준은 아래와 같다.

### 01, 02 문서의 판정 기준

판정은 케이스마다 세 가지를 O, △, X로 매긴다. 수치가 아니라 원본을 읽고 내린 판단이고, 근거를 리포트에 함께 적는다.

| 항목      | O                                  | △                                                            | X                                       |
| --------- | ---------------------------------- | ------------------------------------------------------------ | --------------------------------------- |
| 도구 호출 | 맞는 도구와 인자로 오류 없이 끝냄  | 결과는 맞지만 오류, 헛도는 호출, 불필요한 인자가 있었음      | 요청한 일을 못 했거나 다른 일을 함      |
| 충실도    | 답의 내용이 모두 도구 결과에 있음  | 도구 결과에 없는 내용을 조금 덧붙이거나 일부를 전체처럼 말함 | 도구 결과와 다르거나 없는 사실을 지어냄 |
| 응답 품질 | 요청에 바로 답하고 군더더기가 없음 | 답은 했지만 장황하거나, 내부 ID를 노출하거나, 언어가 어긋남  | 답이 없거나 사용자가 쓸 수 없는 글      |

- 충실도는 답을 낸 케이스만 매긴다. 답이 없으면 `-`로 적는다.
- 하네스의 통과 여부와 판정이 다르면 리포트에 따로 적는다.
